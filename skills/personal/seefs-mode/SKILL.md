# Seefs 模式

本技能叠加在当前环境的全局规则（`global-agents/` 对应的 `AGENTS.md` / `CLAUDE.md`）之上。全局规则已覆盖优先级、确认边界、浏览器授权、测试克制、一手信源核对、根因扫同类、界面底线、有界检索与中文行文，本文件只补充增量工作流与节点技能路由，各节技能只引用其名，不内联正文。

## 决策、建模与实证

- 默认用户熟悉 Rust、Go、Python、TypeScript 与主流生态，直接进入工程判断，跳过基础教学，把上下文留给真正决定成败的问题。
- 改老代码前遇到反直觉设计，先用 `/why` 从提交和 PR 历史追查当初动机，避免把历史护栏当冗余删掉；需要梳理领域术语或模块边界时，借助 `domain-modeling` 与 `codebase-design` 对齐口径。
- 面对模糊或跨模块需求，先厘清状态、边界与变更影响，再按投入产出比抓 1 到 3 个高杠杆改动，避免为求完整把改动面铺大。涉及状态机、生命周期或并发事件交错时，写代码前先用 `state-modeling` 画出最小状态图；若并发交错决定正确性，提示用户用 `/statechart` 做模型检验。
- 认为需求、范围或设计不合理时直接反驳并说明理由，附和只会推迟返工；用户否决某子项后直接裁掉并重排剩余方案。
- 能通过跑最小命令或代码原型拍板的分叉，直接运行验证或用 `prototype` 拿实证，不靠口头争论消耗往返。

## 调试、评审与防复发

- 处理疑难或偶发故障时，先建一条单一、确定、快速且能稳定变红的复现命令（可调用 `diagnosing-bugs`），再提假设与改代码，避免无复现盲猜。
- 报出性能或基准对比数字前，先按 `/benchmark-checklist` 核对测试口径，确认测的是目标路径而非缓存或冷启动噪声，只交真实测得的耗时拆解、重渲染次数、请求频次、包体 KiB 或落盘字节。
- 改动公共模块、共享状态或高影响路径后，用 `/blast-radius` 查清 diff 之外的波及面；高风险改动需对抗验证时建议跑 `/interrogate`，常规分支审查与 PR 说明交给 `code-review` 和 `pr`，前端或移动端视觉改动用 `ui-diff` 对比前后画面。
- 对外输出长文或修改 Agent 文档时，过一遍 `/unslop`、`humanizer` 或 `writing-for-agents`，压掉 AI 腔和废话。
- 同类错误重复出现时，按「架构消除 > 类型约束 > lint 或校验门禁 > 文档规则」把教训固化进结构，而不是指望下次靠记忆避坑：沉淀代码门禁建议跑 `/correct`，修仓库环境或流程建议跑 `/retro`，反哺已有技能建议跑 `/reflect`。

## 委派与模型选型

- 创建子代理时，在 brief 首行写明先读本文件（`seefs-mode/SKILL.md` 的绝对路径），因为手动触发的模式技能不会自动进入子代理上下文；其余内容只放目标、边界与文件路径指针，减少上下文噪声。
- 委派前先查询当前环境实际可用模型列表，不写死具体版本号，避免模型更迭后路由失效。按任务职责选用强项模型（逻辑、协议、数据流与 UI/UX 交互各取所长），跨模型评审优先选择不同厂商以防同源盲区。
